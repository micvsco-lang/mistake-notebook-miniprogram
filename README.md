# 错题订正 · 知识强化

一个微信小程序：把学习通发回来的作业收进来 → 逼自己写下「错在哪」→ 看系统归因 → 针对性刷题。

数据全部存在本机，不连服务器，不需要备案域名。

> **起源**：最初是个人自用工具（东南大学，工科数学分析 + 线性代数），现在开源，欢迎一起完善。

> ## 📌 这是一个半成品，作者在招人一起做
>
> **做得不错的部分**：7 个页面与状态机、错因分析、巩固训练、146 个知识点树、
> 手机抓取脚本、四层校验共 **628 项测试**。开箱即可编译，不用配任何东西。
>
> **最大的缺口**：拍照识别目前**依赖云端视觉大模型**（要花钱、要配 Key、图片要出本机）。
> 作者想把它改成**完全本地运行、零 API、零成本、离线可用**，但这块**还没人做**。
>
> **缺的核心是**：把一张已批改的作业照片，自动切成「题干 / 我的解答 / 教师批语 / 得分」四栏，
> 并尽量把里面的字转出来。
>
> 👉 **想帮忙的看这份文档**：[ROADMAP-本地识图.md](ROADMAP-本地识图.md)
> 里面写清了现状、已有的可复用代码、要解决的技术难点、以及两条难度不同的路线
> （**建议从「区域分割」入手，难度中等、见效快**）。
> 只会写代码不够 —— **先开 Issue 讨论思路比直接提 PR 更有价值**。

## 一、跑起来（三步）

1. 装 **微信开发者工具**（稳定版即可）。
2. 打开工具 → **导入项目**：
   - 目录选：你克隆下来的 `错题订正小程序` 文件夹
   - AppID 选：**测试号**（工具提供的「测试号 / 不使用 AppID」）
3. 点 **编译**。

进「今日」页就能看到 5 道真实错题——题目、公式、手写作答照片、老师逐题批语都在。

> **关于 AppID**：仓库里的 `project.config.json` 用的是 `touristappid`（游客模式），
> 所以**开箱即可编译**，你不需要先改任何东西。
> 想在自己手机上跑，才需要换成你自己的 AppID，见第四节。

**不需要**注册小程序、不需要云开发、不需要任何 Key —— 直接编译就能看到全部界面和种子数据。
云端识别（拍照提取文字）是可选功能，见第八节。

## 二、里面已经装好的数据

种子数据是从学习通收件箱抓下来的真实作业，题目、公式、手写作答照片、老师逐题批语都在：

| 题号 | 考点 | 得分 | 归属错因 |
|---|---|---|---|
| Q1 | 无上界／无下界的定义表述 | 20/20 | —（满分，不进错题本） |
| Q2 | 数集上下确界是否存在 | 15/20 | C2 证明结构不完整 |
| Q3 | A={x∈Q \| x²<2} 在 Q 内无上确界 | **6/20** | C3 推理不严谨 + C4 漏分类讨论 |
| Q4 | 去心邻域内无上界、无下界 | 17/20 | C6 表述与书写不规范 |
| Q5 | 数集上下确界并证明 | 18/20 | C6 表述与书写不规范 |

知识点与错因是**逐题对着教师批语人工标注**的，不是猜的。比如 Q3 那条：

> 构造量 ε=[M−√2]+1 逻辑不严谨，未完成「任意有理数上界都不是最小上界」的核心论证；未对 M²<2 与 M²>2 分类讨论。

## 三、有一件事比功能更重要：顺序不能反

这个品类的价值全在**顺序**上：

```
记录「我错了」 → 写下「为什么错」 → 才解锁分析 → 训练怎么练
```

所以「错因分析」区块在提交订正前是**锁着**的。不是交互设计的花样——一旦反过来（先给解析、再让你订正），它就变成拍题出答案的工具，对你自己没有任何价值。

状态机也是从这个顺序长出来的：

```
new（待订正） ──提交订正──▶ analyzed（已分析） ──训练──▶ training ──连对2次──▶ mastered
                                                              ▲                  │
                                                              └──── 答错退回 ─────┘
```

首页的「待订正」、复习排程、周报数字，全部由它派生。

## 五、界面导览

| 页面 | 干什么 |
|---|---|
| **今日** | 概览 + 待订正清单（失分多的排前面）+ 到期的复习提醒 |
| **错题本** | 按状态筛选、搜索；每道题可直接去订正或训练 |
| **详情** | 题干、我的答案、正确答案、批语；**我的疑惑**（对 AI 批语的异议标注，不影响订正与解锁）；订正后解锁错因分析；可手动改判错因、调整知识点 |
| **订正** | 四个引导问题 + 手写输入 + 拍订正稿；提交即解锁分析 |
| **训练** | 判断题／选择题／填空题／排序题，答完自动判分并给解析 |
| **统计** | 掌握进度、错因分布、知识点强弱、下一步建议 |
| **导入与备份** | **拍照识别**（主入口，照片→自动拆题）、粘贴作业包、手动录入、导出备份、清空重置 |

**公式图的处理**：学习通把公式渲染成图片，所以题干是「文字 + 行内小图」混排的。这里没有用 `rich-text`（它对行内图尺寸几乎不可控），而是在构建期把 HTML 解析成节点数组，运行时用 `text` / `image` 精确排布——单符号图与正文字号齐平，长公式满宽但不溢出。点任意公式图可放大看原图。

**「我的疑惑」**：批语是 AI 判的，可能出错（把手写 σ 认成 6 再批「符号写错」）。详情页里可以对每道题标注疑惑点（判错／符号被认错／看不懂／其他），错题本列表也会显示 ❓ 标记。疑惑点只是一种存疑记录——它不影响状态机、不触发解析解锁，和订正是两回事。

## 六、导入新作业

**手机上最省事的是「截图导入」**（导入与备份页第一个 tab，默认就停在这里）：

在学习通里把作业页截图 → 发给微信「文件传输助手」（或直接从相册选）→ 一张图当作一道题原样搬进错题本。
**不识别、不分析、不丢东西**：题干就是那张截图，原图在详情页里能放大对着看，
题干文字和知识点之后在小程序里补。这条路**全程不碰电脑、不需要云函数、不花一分钱**。

> 为什么截图也能算「知识点留空」：整份作业丢进来时没人知道每道题归哪个知识点，
> 硬要选一个只会把人拦在门外。所以截图入库允许 `kp` 为空，之后在详情页补。

**想让 AI 帮你拆题就用「拍照识别」**（同一 tab 的第二块）：

拍一张已被老师批改的作业照片 —— 或者直接把学习通的截图存进微信「文件传输助手」再选 ——
系统会调视觉模型把这张照片拆成若干道题，**题目、你的解答、老师批语、得分、知识点**分别提取出来。
一张照片里有几道题就拆几道；识别结果逐条可改，确认后整批入库。

> 识别难免有错字，所以每道题都能展开改，详情页也保留了**原始照片**随时对照。
> 识别出来的题跟手动录入的一样，**解析是锁着的** —— 拍照只是把题目搬进来的方式变了，
> 不改变「先写错在哪，才解锁分析」这个顺序。

**手写符号对照**（拍照识别页底部，可展开）：视觉模型看手写体时最容易把 σ 认成 6、
把 ε 认成 3——老师用的 AI 判卷也犯过一模一样的错。所以这里内置了一张常见手写符号
对照表（`miniprogram/data/symbols.js`），它有两个用途：

1. **已内置进识别流程**：每次识别都会提示模型「手写符号按上下文取标准符号转录，
   不要照抄形状」——形状差异不是错误；
2. **给人查**：识别结果里出现奇怪的字符时展开这张表，一眼就能看出原稿写的可能是什么。

### 没开云开发也能用

云端识别需要在 `miniprogram/utils/recognize.js` 里填一个云开发环境 ID，并部署
`cloudfunctions/recognizeWork`（详见 `cloudfunctions/README.md`）。

**没配的时候不会坏，会降级**：照片仍然能选、能入库，只是不作文字提取 ——
照片本身直接当作题干存进去，题目和批语你后面在详情页补。顶部的黄色提示会告诉你当前是哪种模式。

### 把整份作业搬进来的四条路

按「简单优先」排：

**① 截图导入（推荐，手机上最省事）**——见上面那一段。一张图一道题，不碰电脑、不要 Key。

**② 在手机上直接抓（进阶、可选，免电脑、零费用）**——导入页「粘贴导入」tab 顶部，展开后点「复制脚本」：

把那段脚本装进手机浏览器，回到小程序粘贴即可。脚本只在你自己的浏览器里读当前页面，
**不联网、不上传、不需要云函数和 API Key**。

> 这条路是「锦上添花」不是「必经之路」：它能把文字、公式图、手写照片一次性全搬进来，
> 代价是要先给手机浏览器装一个脚本。**装不上就跳过，用 ① 一样能搬**，只是题干变成图片。
> 安卓上 Via 的「导入脚本」是按油猴格式解析的，格式不对会报「解析脚本失败」。

**它做的是「原样搬运」**，不做任何识别与分析：

- 题干文字、每张公式图、数字、**手写解答的照片**、批语、得分，全部按页面上的原位置一起带走 ——
  文字和公式图在数组里是交替的，导进小程序后顺序和排版跟原页面一致；
- **不识别手写内容**。你的手写解答是以照片形式搬进来的，能看能对照，但不会被当成文字处理；
- **没批改的作业也照搬**。学习通上很多作业没有教师批语（没得分也没判词），脚本不会因此少搬东西，
  一份作业的题一道不落（导入包带 `importAll` 标记），要不要算错题、怎么整理，都由小程序侧决定。

> 搬运时页面上会直接报「搬到 N 道题（含 X 张公式图、Y 张手写照片）」——
> 图片是这条链路最容易丢的东西，所以让你一眼就能确认，不用等导进小程序才发现公式变空白。

三种装法（导入页里会完整列出）：

| 平台 | 装法 | 体验 |
|---|---|---|
| **安卓** | Via 浏览器的「设置 → 脚本 → 导入脚本」加载 `抓作业-手机脚本-自动版.js`（`node tools/export-grab-script.js` 生成） | **最省事**：打开作业页自动抓，什么都不用点 |
| 安卓 | Via / X 浏览器 / Kiwi 建书签，网址栏贴 `javascript:` 开头的脚本 | 打开作业页点一下书签 |
| iPhone | 快捷指令「在网页上运行 JavaScript」 | 作业页点「分享」选它 |

> Via 的「导入脚本」是**按油猴（UserScript）格式解析**的：自动注入版必须带 `// ==UserScript==` 元数据块，
> 否则会报「解析脚本失败」；而且要走「导入脚本 → 选文件」，把网页上的脚本文本直接粘进去不行。
> 真装不上就别耗着 —— 回 ① 截图导入，五分钟就能搬完一份作业。

> 手机版 **Chrome 会忽略收藏里的 `javascript:` 地址**，别在 Chrome 上折腾书签。

> **入口可以是学习通 App**：App 里的作业本来就是一张网页，所以可以在 App 里打开作业 →
> 「··· / 分享」→ 复制链接 → 用手机浏览器打开，再执行脚本。
> 但两件事做不到：① App 里执行不了脚本（系统不允许往别人的 App 注入代码，iOS 更严）；
> ② **App 的登录态带不到浏览器**，第一次会跳登录页，在浏览器里登录一次后就顺了（脚本碰到登录页会直接提示）。

> ⚠️ **微信里做不了这件事**，两条路都堵死：微信内置浏览器没有地址栏和书签，无法往第三方网页注入脚本；
> 小程序内嵌网页要用 `web-view`，而微信规定「业务域名仅非个人主体可配置」，且需把校验文件放到对方域名根目录。
> 微信真正能帮的是**搬运**：脚本结果进剪贴板后，回来粘贴即可。

**③ 粘贴导入**：支持单份作业（含 `questions`）或作业包（含 `assignments` 数组）两种格式。
格式样例见 `miniprogram/data/sample-import.js`。想先试试流程，点「载入示例」会填入一份线代作业（含 2 道错题）。

> 抓取脚本的本体是 `miniprogram/data/grab-script.js` 里的 `BOOKMARKLET`，
> 由 `tools/build-grab-script.js` 从采集端解析器生成。
> 采集端（浏览器插件）是作者本地的私有工具，未包含在本仓库；想接自己的采集端，
> 用 `CHAOXING_PARSER=<parser.js> node tools/build-grab-script.js` 指向它即可，
> 只要暴露 `window.__CXC__.extractSync()` 就行。

**④ 手动录入**：一次一道，适合刚被扣分时立刻录进来。

**注意**：**只收已批改错题**是默认行为（种子数据都批改过，这样错题本干净）。
但手机抓取的产物带 `importAll`，会把整份作业的题全部导入 —— 因为学习通上大量作业压根没有批语，
按「只收错题」会把整份作业滤成 0 条，而你想先搬进来再自己整理。
截图导入走的也是「全量收录」：一张图一道题，一题不落。

## 八、可选：接 AI

> ⚠️ **这一节描述的方案正在被替换掉。** 现有的拍照识别跑在云端视觉大模型上，
> 要花钱、要配 Key、图片要出本机。作者希望改成**完全本地、零 API** 的实现，
> 但那块**还没有人做** —— 详见 [ROADMAP-本地识图.md](ROADMAP-本地识图.md)。
> 如果你想参与，那里的缺口正是你要做的事；本节留作参考，说明现状是什么。
>
> 想参与本地识图改造的，**先读第八节了解现状就够了，不必按下面的步骤部署云函数。**

两个云函数都是**可选**的，不部署也能完整使用：

| 云函数 | 不部署时会怎样 | 部署后 |
|---|---|---|
| `recognizeWork` | 拍照录入退化为「照片即题干」 | 自动提取题干／解答／批语／得分／知识点 |
| `analyzeCause` | 错因归类走规则引擎（批语清楚时够用） | 批语含糊或没有批语时也能归因 |

**拍照识别只需三步**（详细说明见 `cloudfunctions/README.md`）：

1. 在 `miniprogram/utils/recognize.js` 顶部把 `CLOUD_ENV` 填成你自己的云开发环境 ID；
2. 在微信开发者工具里部署 `cloudfunctions/recognizeWork`；
3. 在云函数配置里加一个环境变量 `VLM_API_KEY` = 你的大模型 API Key，**并把超时改成 60 秒**（默认太短，视觉模型一次要几秒到十几秒）。

**换模型只改环境变量 `VLM_PROVIDER`**，内置五种预设：

| `VLM_PROVIDER` | 模型 | 说明 |
|---|---|---|
| `zhipu`（默认） | `glm-4.6v-flash` | 智谱 GLM，**有免费档**，注册最快 |
| `kimi` | `kimi-k3` | 月之暗面，原生视觉，手写数学转录实测质量好；按量付费无免费档 |
| `qwen` | `qwen3-vl-plus` | 阿里通义千问 |
| `doubao` | `doubao-seed-1-6-vision-250815` | 字节豆包（火山方舟） |
| `deepseek` | `deepseek-v4-flash-vision-exp` | 实验版，**单图上限 384 token**，长题会看不清 |
| `custom` | 自己填 | 任何 OpenAI 兼容端点，配 `VLM_ENDPOINT` + `VLM_MODEL` |

> **选型陷阱：旗舰 ≠ 能看图。** GLM 的 5.3 旗舰版是纯文本模型，传图会报错；能看图的是 `glm-4.6v-*` 系列。
> 挑模型时看名字里有没有 `v`（vision），别只看版本号大小。
>
> 选型别靠排行榜，用仓库里的 `tools/compare-vlm.js` 拿**你自己的作业照片**实测横向对比。

**为什么不把它们做成必需**：规则引擎已经能把 HW1 这 5 道题归对，而 AI 会引入 API 成本和不确定性。
更需要先验证的是——你愿不愿意为了「看清自己为什么错」多花那一步。如果这一步不愿意，AI 也救不了。

## 十一、常见问题

**编译报错说 AppID 无效／无权限？**
仓库版用的是 `touristappid`（游客模式），正常情况下不会报这个错。如果你改成过自己的 AppID 又改错了，把它改回 `touristappid` 就能恢复。见第一节和第四节。

**拍照识别点了没反应，或者提示「云端识别未开通」？**
这是**预期行为**，不是 bug —— 你还没配云开发。没配的时候功能会**优雅降级**：照片仍能选、能入库，只是不做文字提取，照片直接当题干存。要启用，见第八节。

**配了云开发但识别总是超时？**
云函数默认超时时间太短。到云开发控制台把 `recognizeWork` 的**超时时间改成 60 秒**。视觉模型一次调用要几秒到十几秒，默认值必然不够。

**识别出来的字有错？**
正常现象，视觉模型不是 OCR。详情页保留了**原始照片对照**，随时可以核对。识别结果在入库前也逐条可改。

**为什么识别出来的题还要我自己写订正？**
这是刻意的（见第十二节）。拍照只是换了种方式把题搬进来，不改变「先写错在哪，才解锁分析」的顺序。

**`tools/e2e-simulator.js` 跑不起来？**
它需要微信开发者工具**已启动且服务端口已开**，并用 `NODE_PATH` 指向已安装 `miniprogram-automator` 的目录。日常提交 PR 只需要跑前三个脚本（`check.js` / `test-logic.js` / `test-pages.js`），不依赖开发者工具。

**我没有学习通的作业数据，能玩吗？**
能。项目自带 HW1 的 5 道真实错题作为种子数据，编译就能用。想导入自己的作业，见第六节。

## 十二、边界（别越过）

> ⚠️ **给协作者**：本节是这个项目的**产品红线**。下面每一条都是刻意的设计约束，不是待修的 bug。
> 提 PR 前请确认没有触碰它们 —— 尤其是第一条。

**1. 解析必须在订正之后才解锁 —— 这是唯一不可协商的一条。**

`store.submitCorrection()` 里订正内容为空会直接拒绝；「错因分析」区块在提交订正前是锁着的。
拍照识别出来的题，也一律落成「待订正」状态、解析同样锁着。

一旦反过来（先给解析、再让你订正），它就变成拍题出答案的工具，对使用者没有任何价值。
**任何绕过这道闸门的改动，无论功能多好都会被拒绝。**

**2. 知识点只能从预置树里选，不许自由生成。**（`utils/kp.js`）
允许模型或用户自由命名知识点，同义节点会污染掌握度统计，整棵树的统计立刻失效。

**3. 错因固定 7 类，不许扩展。**（`utils/cause.js`，C1–C7）
理由同上：分类体系一旦可以自由生长，分布图就没有意义了。云函数里对模型输出做白名单硬过滤。

**4. 数据边界：只处理使用者自己账号、自己看得到的内容。**

- 不做代登录（不存任何人账号密码／会话票据）
- 不批量拉取他人的作业
- 不引入除「拍照识别发往使用者自己的云开发环境」之外的任何网络请求

这几条不是洁癖，是这个工具对使用者还有用的前提。
