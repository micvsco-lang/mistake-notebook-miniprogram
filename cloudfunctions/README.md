# cloudfunctions（可选）

**这个目录不部署也不影响使用。**

- `analyzeCause` 不部署 → 错因归类走小程序的规则引擎（批语清楚时够用）
- `recognizeWork` 不部署 → 「拍照识别」退化为「照片直接当题干」，仍然能录入

---

## recognizeWork · 拍照识别（强烈建议部署）

把一张**已批改作业**的照片转成结构化题目：题干、我的解答、教师批语、标准解答、得分、知识点。

### 为什么是视觉大模型，而不是 OCR

纯 OCR 只给一串纯文本，会丢掉**版面语义** —— 哪段是印刷的题干、哪段是学生手写的解答、
哪段是老师红笔的批语。而这三段恰好是这个 App 的核心字段，分不开就等于没识别。
视觉模型一次调用同时完成「认字 + 分栏 + 判色」，比 OCR 后再拿规则去猜可靠得多。

一句话区分：

- **OCR 回答的是**：图上有什么字、在什么位置。
- **我们要的是**：哪段是我写的、哪段是老师用红笔批的。

第二条是**视觉属性 + 语义判断**，不是文字识别。所以这个 App 要的是「能理解版面的视觉模型」，
不是「识别率最高的 OCR 模型」—— 哪怕后者认字更准，它交出来的仍是一锅粥，没有分栏。

### ⚠️ 控制台里那个叫 `GLM-OCR` 的，别选

智谱官网把 `GLM-OCR` 单列为「视觉模型 · 文档解析与结构化提取」，是**唯一名字里带 OCR 的**，
所以很容易被它吸引。但它恰恰不适合这里，三个原因：

| 问题 | 说明 |
|---|---|
| **分不清红笔批语** | 它的版面标签是 `text` / `table` / `formula` 这类**结构标签**，不是「这段是老师红笔写的」。而分栏正是本 App 的全部价值所在 |
| **上下文只有 8K** | 一页作业 + 知识点清单 + 输出，8K 很可能装不下。而 GLM-4.6V-Flash 有 128K |
| **接口不兼容** | 它走独立的 `/paas/v4/layout_parsing`，不是标准 `chat/completions`。要用得改云函数的调用代码 |

> 有意思的是：**`GLM-OCR` 本身就是基于 GLM-V 架构做的**（官方说明：建立在 GLM-V
> 编码器—解码器框架之上，0.9B 参数）。所以它不是「V 的替代品」，而是「V 架构摘出来
> 专做文档解析的一个小分支」—— 能力是 V 的真子集，还砍掉了通用视觉理解。

**结论：名字里带 OCR 的那个，是这条路的三岔口上最容易走错的那个。**

### 部署步骤

1. 开发者工具里点 **云开发** → 开通环境（个人主体可开通，有免费额度）→ 复制**环境 ID**。
2. 把环境 ID 填进 `miniprogram/utils/recognize.js` 顶部的 `CLOUD_ENV`：

   ```js
   let CLOUD_ENV = 'cuoti-3g8xxxxx';   // ← 换成你的
   ```

3. 右键 `cloudfunctions/recognizeWork` → **上传并部署：云端安装依赖**。
   （本函数**零依赖**，不用装 wx-server-sdk，几秒就好。）

4. 在云开发控制台 → 云函数 → `recognizeWork` → **配置** 里做两件事：

   | 项 | 值 |
   |---|---|
   | 环境变量 `VLM_PROVIDER` | 选一家：`zhipu`（默认）/ `kimi` / `qwen` / `doubao` / `deepseek` / `custom` |
   | 环境变量 `VLM_API_KEY` | **必填**，对应厂商控制台申请 |
   | 环境变量 `VLM_MODEL` | 选填，覆盖该厂商的默认模型 |
   | 环境变量 `VLM_ENDPOINT` | 选填，覆盖接口地址（`custom` 时必填） |
   | **超时时间** | **改成 60 秒** ← 默认太短，视觉模型一次要几秒到十几秒 |

   换模型 = 改环境变量，**一行代码都不用动**。所有预设都走 OpenAI 兼容协议。

5. 重新编译小程序，进「导入与备份 → 拍照识别」，顶部那句黄色提示会消失，变成正常说明。

> **没配 `VLM_API_KEY` 时会自动退回读 `LLM_API_KEY`**（analyzeCause 用的那个），
> 但注意 DeepSeek 这类纯文本模型**没有视觉能力**，退过去也调不通。

## 换哪个模型？—— 先看结论

### ⚠️ 常见误区：模型名字里没有「V」的，基本看不了图

**V = Vision = 有眼睛。** 智谱的命名非常一致：同一个代次里，不带 V 的是纯语言模型，
带 V 的是在它上面加了视觉塔的版本。选错了不会"效果差一点"，而是**直接报错**。

| 模型 | 能接拍照识别吗 | 原因 |
|---|---|---|
| **GLM-4-Air / 4.5-Air** | ❌ | **纯文本**。便宜、快，但没有视觉输入。常有人因为"便宜"选它，然后调不通 |
| **GLM-4-Plus** | ❌ | **纯文本，而且贵**。比 Air 强在文本能力上，跟看图没关系 —— 用来识图是纯浪费钱 |
| **GLM-4.5V / GLM-4.6V** | ✅ | 就是 **Air 同一个底座 + 视觉塔**。Air 的语言能力它全有，还多了眼睛 |
| **GLM-5.3**（旗舰） | ❌ | **纯文本模型**，预训练只用了文本，没有视觉输入 |
| **GLM-5.3-Flash** | ✅ | **原生多模态**（官方文档：能原生理解图片视频），1M 上下文，付费 |
| GLM-4.6V / 4.6V-Flash | ✅ | 视觉模型，本来的默认 |
| DeepSeek 其他模型 | ❌ | 传图会报 `This model does not support image`（错因分析用纯文本没问题） |
| **DeepSeek `deepseek-v4-flash-vision-exp`** | ⚠️ | **唯一能传图的**（实验版）。便宜、国内直连，但**每张图上限 384 token**，图片压得比较狠，手写小字可能不够看清 |
| 通义 qwen3-vl 系列 / qwen-vl-ocr | ✅ | 视觉模型，`qwen-vl-ocr` 是专门的文字提取模型 |
| 豆包 doubao-seed-*-vision | ✅ | 视觉模型，但要在方舟控制台**单独开通**才调得通 |
| **Kimi `kimi-k3`** | ✅ | **原生视觉**（图/视频输入）。只认 base64 传图（本项目默认正是这个）。按量付费、无免费档。2026-09-24 用旋转 90° 的手写数学证明页实测，转录质量良好 |
| ChatGPT / OpenAI 官方 | ❌（直连） | 国内网络从 2023 年起连不上 `api.openai.com`，**云函数在国内，必挂**（本机实测 `fetch failed`） |

> **一句话记住：在 Air 和 V 之间犹豫时，答案永远是 V。**
> 因为 `GLM-4.5V` 的底座就是 `GLM-4.5-Air`（官方架构说明：Air MoE backbone + vision tower）。
> V = Air 的全部能力 + 看图。不存在"为了省钱选 Air"这回事 —— Air 根本接不了这个活。

### 免费的视觉模型有三个（2026-09-25 官方文档页实抓）

`docs.bigmodel.cn/cn/guide/start/model-overview` 的「视觉理解模型」分类下，标着「免费」的：

| 免费视觉模型 | 上下文 | 最大输出 | 评价 |
|---|---|---|---|
| **GLM-4.6V-Flash** ← 默认 | **128K** | 32K | 三者中上下文最大，官方标注「支持视觉推理」 |
| GLM-4.1V-Thinking-Flash | 64K | 16K | 备选；带 Thinking，适合需要推理的图 |
| GLM-4V-Flash | 16K | 1K | 太小：一页作业的输出就可能顶到 1K 上限，**不推荐** |

> **结论：默认的 `glm-4.6v-flash` 已经是免费视觉模型里的最优解** —— 上下文最大（128K）、
> 输出上限最宽（32K）。想升级是去换**付费**的 `glm-4.6v` 或 `glm-5.3-flash`（1M 上下文原生多模态），
> 不是在免费模型里来回换。

（同页还有付费的 `GLM-5V-Turbo`（200K，多模态 Coding 基座）和 `AutoGLM-Phone`（手机操作框架，与本场景无关）。）

### 推荐顺序（按「这活儿的实际瓶颈」排）

这活儿的难点不是「模型聪不聪明」，是三件很具体的事：
**① 认中文手写体 ② 还原数学符号（ε δ ∀ √ 分数） ③ 分清红笔批语和正文**。
排行榜第一名未必这三项都强，所以最终以你自己的照片实测为准（见下一节）。

1. **`glm-4.6v-flash`（免费）** —— 先用它验证效果，一分钱不花。
   ⚠️ 但**高峰期会频繁 429**（免费池排队，实测晚间约一半请求被拒）。做长期主力不合适。
2. **`glm-4.6v`（付费旗舰视觉）** —— 长期使用的推荐档。**付费池不排队**，这是它相对
   免费版最大的价值（不是"更聪明"）。官方价：输入 1 元 / 输出 3 元 每百万 token。
3. **`glm-4.6v-flashx`** —— 想更省就用它：输入 0.15 / 输出 1.5（约为旗舰的 1/6 与 1/2）。
4. **`glm-5.3-flash`** —— 更新一代多模态（输入 0.8 / 输出 2.8），想尝鲜可试。

#### 智谱视觉模型价目（元/百万 token，2026-09-25 官方价格页）

| 模型 | 输入 | 输出 | 备注 |
|---|---|---|---|
| GLM-4.6V-Flash | 免费 | 免费 | 高峰排长队 |
| **GLM-4.6V-FlashX** | **0.15** | **1.5** | 付费池，最省 |
| **GLM-4.6V** | **1** | **3** | 旗舰视觉 |
| GLM-5.3-Flash | 0.8 | 2.8 | 新一代 |
| GLM-4.5V | 2 | 6 | 上一代，更贵 |
| GLM-OCR | 0.03 | 0.03 | 文档解析，**分不了栏**，别用 |

#### 一页作业到底多少钱（用实测 token 算）

一页作业（约 500KB 的图）实测：输入 ≈ 6200 token（图片约 5600 + 提示词约 700），
输出 ≈ 500（关掉 thinking 之后）。

| 模型 | 每页 | 一学期 90 页 |
|---|---|---|
| GLM-4.6V | ≈ 0.008 元（**不到 1 分**） | **≈ 0.7 元** |
| GLM-4.6V-FlashX | ≈ 0.002 元 | ≈ 0.16 元 |

**结论：充 10 块钱够用好几年。** 所以长期使用该纠结的是识别准不准，不是贵不贵。

> ⚠️ **不要为了省钱选 DeepSeek 的视觉模型**（`deepseek-v4-flash-vision-exp`）：
> 它官方限定**单张图最多 384 token**（上述作业图在 GLM 下约占 6200），
> 等于只看到 1/15 的信息量 —— 手写公式压到那个程度基本糊了。便宜但做不了这活儿。
4. **`kimi-k3`（`VLM_PROVIDER=kimi`）** —— 月之暗面的旗舰，原生视觉。如果你本来就有
   Kimi 的 API 额度，直接用。没有免费档，按量付费。
5. **`qwen3-vl-plus`（`VLM_PROVIDER=qwen`）** —— 交叉验证用。两家意见不一致时，谁对听谁的。
6. **`deepseek-v4-flash-vision-exp`（`VLM_PROVIDER=deepseek`）** —— 如果你已经有 DeepSeek 的
   Key 和余额，这个最省事（不用再注册一家）。但它有两个前提：模型带 `-exp` 是实验版，
   且**单图 token 上限只有 384**（图片会被大幅压缩）—— 手写小字和数学符号这类细节够不够看清，
   必须实测。建议拿它跟 GLM 对比一次再决定。
7. **豆包** —— 便宜，但记得先在方舟控制台把模型**开通**，否则报「模型不存在」。

### 不推荐 ChatGPT 的三个理由

1. **连不上**：云函数跑在腾讯云国内节点，直连 OpenAI 被网络阻断，本机都实测 `fetch failed`。
2. **要走中转就得上第三方**：图片（你的作业）要经过第三方服务器转发，隐私没保障。
3. **不值**：它的中文手写 OCR 并不比 GLM/Qwen 强。花更多钱、担更多风险，换不来这个场景的收益。

## 用自己的照片实测：compare-vlm.js

选型不要靠猜。工具箱里有一个对比脚本，用**同一张真实作业照片**横向跑多个模型：

```bash
# 1. 生成 Key 模板（只会生成一次）
node tools/compare-vlm.js --init
#    → 打开 tools/vlm-keys.json，把想试的那几家的 Key 填进去

# 2. 拿一张真实作业照片来比（手机拍的原图直接丢给它）
node tools/compare-vlm.js 拍的作业.jpg
```

产出：`tools/vlm-compare/<时间戳>.html` —— 各模型按题号**并排对照**，
空字段标黄、「□」未认出的字标橙。脚本自动体检：题干/解答/批语缺了几处、
认不出几个字，一眼看出谁行谁不行。

**怎么读结果**：

1. 先看**教师批语**栏 —— 分不清红笔和正文的模型，这栏会空或混进题干；
2. 再看数学符号有没有还原（ε δ ∑ √ 分数）；
3. 最后数「□」—— 那是它没认出来的字。

脚本复用的是云函数里**同一份提示词**和知识点过滤规则，所以测出来的效果 ≈ 线上真实效果。

> `tools/vlm-keys.json` 里是明文 Key，已加进 `.gitignore`，**别截图发给别人**。

### 微调开关（环境变量，一般不用动）

| 变量 | 作用 |
|---|---|
| `VLM_LITE` | **提示词档位**，见下表。长期使用建议 `2` |
| `VLM_IMAGE_STYLE` | `dataurl`（默认）/ `raw`。个别厂商不认 `data:` 前缀时改 `raw` |
| `VLM_THINKING` | `1` = 开智谱深度思考，更准但更慢更贵 |
| `VLM_JSON_MODE` | `1` = 强制 JSON 输出，更稳；个别模型不认这个参数 |
| `VLM_MAX_TOKENS` | 默认 4000。一页作业题多时输出会长 |
| `VLM_MAX_RETRY` | 默认 2。对 429 / 5xx / 网络错误自动退避重试（401 不重试，Key 错了等多久都错） |

#### 提示词档位 `VLM_LITE` —— 唯一真正影响长期花费的开关

系统提示词每次调用都要重发一遍，属于**固定开销**。用得越久，这笔钱累积得越多，
所以它单独做成了可分档：

| 档位 | 适用 | 提示词字数 | 含知识点+符号的固定开销 |
|---|---|---|---|
| 不设置 | 翻拍纸质作业（会旋转、背面透字、有污渍） | 1366 | 1659 字 |
| `1` | 屏幕截图 | 1158 | 1451 字 |
| `2` | 屏幕截图，**长期使用推荐** | 430 | **723 字** |

极简版（`2`）砍掉的都是「模型本来就会的事」：不用交代只输出 JSON、不用列题型枚举、
不用说明极限怎么写。留下的只有四条删了必错的：**分四栏、取标准符号、不许自己解题、
忠实转录**。

> 砍提示词的代价是输出格式可能不稳。这一点由**下游代码兜底**接管而不是继续求模型守规矩：
> `normalizeQuestions()` 对每个字段做类型校验与默认值，题型走近义归并
> （「简答题」→「解答题」），知识点走白名单过滤，空壳题整条丢弃。
> `tools/test-logic.js` 里有 24 条断言专门盯这件事，其中一组**故意喂格式不规范的野输出**。

### 两个必须守住的约束

**① 知识点白名单硬过滤。** 小程序把预置知识点树的名字清单一起发给云函数，
云函数对模型返回的 `kpNames` 做交集过滤 —— 命中不了的直接丢弃。

理由和错因表、知识点树完全一致：一旦允许模型自由命名，用不了多久表里就会冒出
几十个同义不同名的标签，「掌握度统计」会先失去意义，然后整个功能跟着失效。

**② 不允许模型解题。** 提示词里写死了「只转录照片上确实存在的内容，不要自己解题」。
这条是产品边界：拍照只是**把题目搬进来的方式**变了，不该让这个工具从「订正工具」
悄悄变成「拍题出答案」。

配套的：识别出来的题一律以 `status='new'` + `correction=null` 落库，
「先订正才解锁分析」那道闸门在 `store.submitCorrection()` 里，拍照这条路径同样绕不过去
（`tools/test-logic.js` 里有专门的断言盯着这件事）。

## analyzeCause · AI 错因分析

小程序里的规则引擎在批语写得清楚时已经够用。这个云函数是给「批语很含糊、
或者干脆没有批语」的题目兜底：把题目、你的作答、教师批语一起发给大模型，
让它从**预置的错因表**里挑，而不是自由发挥。

### 部署步骤

1. 在微信开发者工具里点 **云开发** → 开通环境（个人主体可以开通，有免费额度）。
2. 右键 `cloudfunctions/analyzeCause` → **上传并部署：云端安装依赖**。
3. 在该云函数的配置里添加环境变量：

   | 变量 | 必填 | 说明 |
   |---|---|---|
   | `LLM_API_KEY` | 是 | 模型服务的 API Key |
   | `LLM_ENDPOINT` | 否 | 默认 `https://api.deepseek.com/v1/chat/completions` |
   | `LLM_MODEL` | 否 | 默认 `deepseek-chat` |

   任何 OpenAI 兼容接口都能用，改 `LLM_ENDPOINT` + `LLM_MODEL` 即可。

4. 在小程序里调用：

   ```js
   wx.cloud.init({ env: '你的环境ID' });

   wx.cloud.callFunction({
     name: 'analyzeCause',
     data: {
       stem: '……', myAnswer: '……', rightAnswer: '……',
       comment: '……', score: 6, fullScore: 20, kp: ['kb_sup', 'kb_dense']
     }
   }).then((res) => {
     if (res.result && res.result.ok) {
       store.setCauses(id, res.result.causes);
     }
   });
   ```

## 一个必须守住的约束

云函数里对模型输出做了**硬过滤**：只接受 `C1`–`C7` 这七个预置代码，其他一律丢弃。

原因和知识点树一样——一旦允许模型自由命名错因，用不了多久表里就会冒出几十个同义不同名的标签，
「错因分布」那张统计图会先失去意义，然后整个归因功能跟着失效。
