错题订正 · 知识强化小程序

把学习通里的作业，变成可复用的错题资产 —— 收录 → 订正 → 归因 → 变式巩固
原生小程序 + 微信云开发 多模态 AI 解析 艾宾浩斯复习 分享裂变获客

0产品定位与三条不可逾越的边界

先定边界，再谈架构 —— 这个品类最容易在审核上翻车。

我们要做的是

一个「错题资产化」工具：学生在学习通写完作业后，把做错的题收进来，系统帮他看清为什么错、并生成同源变式题练到掌握。

  • 输入：学习通作业（收件箱 / 作业页）
  • 加工：结构化 → 归因 → 映射知识点
  • 输出：可复习的错题本 + 训练题 + 掌握度

我们绝不做的是

  • 不做「拍照即出答案」 —— 会被判定为代做 / 作弊工具，审核直接拒，且随时下架
  • 不代写作业、不直接给最终解答 —— 解析必须在用户先行作答之后才解锁
  • 不抓取学习通数据 —— 不逆向、不代登录、不批量拉取他人内容
这是本方案最重要的产品决策。同类产品被下架的主因不是技术，而是定位越界。我们的功能顺序必须是： 先记录「我错了」→ 再分析「为什么错」→ 最后才是「怎么练」。答案永远不能是第一步。 这个顺序同时决定了下面所有数据模型里的 status 状态机。

1核心闭环（一条主链路，五个状态）

每一步都对应一个云函数、一个页面、一次状态流转。闭环闭合在「掌握度」上，而不是「看完解析」。

STEP 1
收录
截图 / 复制文本 / 拍照 → AI 结构化出题干、我的答案、正确答案、所属课程与作业名
→
STEP 2
订正
对照正确答案重做一遍，写下自己的理解。此步之后解析才解锁
→
STEP 3
错因分析
AI 归因到六大错因之一 + 映射知识点 + 给出「你缺的是哪一步」
→
STEP 4
巩固训练
按错因类型生成变式题（换数值/换情境/换问法），作答后即时批改
→
STEP 5
知识强化
掌握度更新 → 艾宾浩斯节点排期 → 订阅消息提醒 → 周报

状态机（mistakes.status）

状态含义触发动作下一状态
new刚收录，未订正用户完成订正（写下订正过程）correcting → analyzed
analyzed已归因，知道错在哪完成一轮变式训练且全对training
training训练中，掌握度累积连续 2 轮跨天训练全对mastered
mastered已掌握，进入低频复习复习失败 1 次回退 training
状态机是整个产品的骨架。首页的「今日待订正」、订阅消息的触发点、周报的数字，全部由它派生。 不要用多个布尔字段（isCorrected/isMastered）来拼，那会让查询和提醒逻辑失控。

2技术架构（原生 + 云开发）

选型理由只有一条：把「服务器、登录鉴权、HTTPS 证书、域名备案」这四件最耗时的事全部省掉，直接换取上线速度。

表现层
小程序原生（WXML / WXSS / JS）· UI 基础组件用 TDesign 小程序版（腾讯官方，与云开发同生态，省掉自研组件成本）· 主包 + 3 个分包控制冷启动
能力层
云函数（Node.js 18） —— 所有 AI 调用、写入校验、配额扣减、内容安全都收口在这一层。小程序端不持有任何密钥
数据层
云数据库（文档型，天然适配错题这种嵌套结构）· 云存储（题目截图，走 CDN）· 两者都能被云函数以管理员身份操作，绕过客户端权限
AI 层
多模态大模型（读图直接出结构化题目，省掉独立 OCR 这一层）· 模型调用凭证只存在云函数环境变量里

为什么不用 Taro / uni-app

你们只投微信一个渠道，多端框架立刻变成净负担：多一层构建链、多一类“编译后行为不一致”的 bug、真机预览链路变长。等真的要多端时再迁移，错题数据都在云上，迁移成本主要在页面层，可控。

成本预期（早期量级）

项说明量级
云开发基础版数据库/存储/云函数调用额度免费额度内可撑过冷启动期
AI 调用一次收录 + 归因 + 出题 ≈ 3 次调用这是唯一随用户量线性增长的成本，必须做配额
云存储题目截图，压缩后约 80–150 KB/张低
AI 成本必须有硬闸门。上线第一天就要有：单用户每日收录上限、图片入库前压缩、失败重试次数上限。否则一个刷接口的用户就能把预算烧掉。

3学习通数据怎么进来（本产品的关键工程问题）

你要求「作业内容从学习通收件箱找」。这里必须先讲清楚技术上能与不能，再给方案。

先排除不可行的路

方案可行性原因
小程序内嵌 web-view 打开学习通 不可行 web-view 要求把 chaoxing.com 配到小程序「业务域名」，而配置需要通过该域名的文件校验 —— 你无法在学习通服务器上放校验文件，这条路直接被封死
小程序后端代登录学习通、拉取收件箱 不可做 要保存用户学习通账密或会话票据，属于合规高危；且涉及抓取第三方平台数据。审核与法务两头都过不去
用学习通开放接口 不存在 学习通未向第三方个人开发者开放作业类接口

可落地的三条路（按投入排序）

MVP 路径 A · 剪贴板导入

用户体验：在电脑上看学习通作业页 → 全选复制 → 打开小程序 → 点「粘贴导入」。

实现：wx.getClipboardData() 拿到文本 → 云函数 importText → 大模型切成结构化题目数组。

优点：零依赖、零合规风险、一天就能做出来，且题目文本质量比截图更高（OCR 不会错）。

缺点：需要用户在电脑上操作一次复制。

MVP 路径 B · 截图 / 拍照

用户体验：wx.chooseMedia 选一张或多张作业截图。

实现：图片压缩 → 云存储 → 云函数把图片 URL 交给多模态模型，直接返回结构化题目（题干 / 我的答案 / 正确答案 / 题号）。

优点：手机端也能用，数学公式、图表、矩阵都能识别。

缺点：调用更贵，需要严格压缩 + 单用户日配额。

V2 路径 C · 电脑端「学习通导入助手」

这是体验最好的一条，而且你们已经有一半资产了 —— 现在这套本地驱动脚本，已经能连上带调试端口的浏览器、读取学习通已登录页面、逐帧解析 DOM。

做法：电脑端把用户自己账号下的作业页解析成结构化 JSON → 生成一个短链 / 二维码（数据存在云上、限时有效、用后即焚）→ 小程序扫码领取。

合规红线（务必守住）：只处理用户本人已登录、本人账号下的页面；数据仅用户可用；不批量、不代理他人账号、不落第三方。本质上是「帮用户把自己看到的内容整理成结构化格式」，而不是「替你抓取平台数据」。

建议排期：不要放进 MVP。先用 A+B 验证「用户是否真的愿意收录错题」这个核心假设 —— 如果连手动导入都不愿意用，自动导入也救不了留存。

关于你收件箱里的那几条作业（高数分析 HW1 09-21、新建作业20260923100409、线代第1次作业-2026-09-22）： 这些正好构成首批种子数据。建议用它们手工跑通一遍「导入 → 结构化 → 归因 → 出题」全链路，把 AI 提示词调到可用，再放量。

4页面树与分包策略

主包只放 tabBar 与核心流程，必须压在 2 MB 以内 —— 这直接决定冷启动速度，而冷启动速度直接影响次日留存。

主包（目标 < 1.2 MB） ├── pages/index/index 首页：今日待订正 / 快速收录入口 / 掌握度概览 ├── pages/capture/capture 收录：粘贴导入 · 截图导入 · 手动录入 ├── pages/review/review 订正：对照答案重做 + 写订正过程 ├── pages/book/book 错题本：按课程 / 知识点 / 错因 / 状态筛选 └── pages/mine/mine 我的：设置、配额、订阅管理 分包 A · packageBook （错题深加工，进入率最高，独立分包避免拖慢主包） ├── pages/detail/detail 错题详情：题干 / 我的答案 / 正确答案 / 订正记录 ├── pages/cause/cause 错因分析报告：归因 + 知识点 + 讲解 ├── pages/drill/drill 变式训练：逐题作答 + 即时批改 └── pages/history/history 训练历史与进步曲线 分包 B · packageKnow （知识强化，中期留存的核心） ├── pages/map/map 知识点掌握度热力图 ├── pages/plan/plan 艾宾浩斯复习计划 └── pages/node/node 单个知识点：关联错题 + 专项训练 分包 C · packageSocial （获客与召回，按需加载） ├── pages/report/report 周报 / 月报（分享卡的落地页） ├── pages/team/team 组队打卡 └── pages/poster/poster 错题海报生成

分包的三条纪律

  • tabBar 页面只能放主包 —— 上面 5 个主包页面就是全部 tabBar 及核心流程，不能再多。
  • 分包之间不互相跳转，只回跳主包。否则会形成隐式依赖，后期拆包会崩。
  • 公共代码放独立分包（subpackageCommon）或主包，别在分包里各抄一份数学公式渲染器 —— 那是体积失控的头号原因。
数学公式渲染是这类产品特有的坑：题干里的 LaTeX 必须渲染。方案用 towxml 或自建 WXSS 渲染层，只放主包一份，分包引用。别用 web-view 渲染公式，会出现高度塌陷。

7AI 设计：错因分类体系与出题策略

这是产品的灵魂，也是与「普通错题本」拉开差距的地方。核心思路：不同错因要用完全不同的巩固手段。

六大错因 → 对应巩固策略（映射关系就是产品壁垒）

错因典型表现AI 要输出什么巩固策略
知识性概念混淆、公式记错、定理条件遗漏指出缺失/记错的具体概念，给出正确定义知识点讲解 + 基础题（先补概念，别上难题）
方法性方法选错、思路中断、没识别出题型指出本题的识别特征与正确方法入口同类题变式 + 方法归纳卡（“看到 X 就用 Y”）
计算性算错、符号错、代入错定位到具体哪一步算错计算专项 + 易错点清单（如分部积分符号）
审题性看错条件、漏条件、理解偏差还原“你理解成了什么” vs “题实际问什么”审题清单训练：划条件、标问题、写已知
规范性步骤缺失、表述不清、单位遗漏指出被扣分的步骤节点步骤模板 + 得分点对照
策略性时间不够、卡壳后放弃给出卡壳后的止损策略限时训练 + 跳过决策练习

三个关键工程约束

  1. 知识点必须从预置知识树里选，不许 AI 自由生成。 做法：把「工科数学分析」「线性代数」的知识点树作为候选枚举塞进提示词，要求模型只能返回候选里的 id。 否则三周后你的知识点表里会出现 200 个同义不同名的节点，掌握度统计彻底失效。
  2. 出题必须带“同源”约束。 变式题要显式指定：同知识点、同题型、换数值或换情境，但不改变解题方法。 并在提示词里禁止出现原题原答案 —— 否则用户只是背下了这道题的答案。
  3. AI 输出一律要走结构化输出（JSON Schema）。 不要让模型返回自由文本再正则去解析。题干里天然带 LaTeX 和换行，正则必然崩。

异步化：别让用户等 AI

一次收录要串三次模型调用（解析 → 归因 → 出题），全部同步等待会超过小程序请求体感上限。设计成：

立即返回

用户马上看到错题进了本子
→
后台

8获客闭环（你要求的“快速获得用户”）

教育类小程序的自然裂变点只有两个：成绩可见的进步 和 同学之间的比较。围绕这两点设计。

机制怎么做为什么有效优先级
错题周报分享卡 每周生成「本周消灭 N 道错题，最薄弱：定积分换元」卡片，可发群/朋友圈 卡片内容自带结果炫耀属性，且点开就是小程序首页（天然落地页） MVP
群入口 · 班级错题墙 同一门课的同学可加入同一错题墙，看到「本课最易错 Top5 知识点」 从「一个人的工具」变成「班级的共同话题」，群内传播天然高效 V2
组队打卡 2–5 人组队，连续订正 N 天解锁成就，断卡全队可见 同伴压力比自我激励强得多，且每拉一个人就是一次拉新 V2
订阅消息召回 艾宾浩斯到点提醒「今天该复习 3 道定积分错题」 错题复习本身就是有时效性的，提醒不是打扰而是刚需 MVP
考前冲刺包 把整学期错题按知识点打包成「考前 30 分钟速览」 考前是使用频次峰值，也是最可能主动分享的时刻 V3
订阅消息有个必须提前知道的限制：一次性订阅消息一次授权只能推一条。所以提醒策略要设计成「让用户在完成订正时顺手点一次订阅」—— 把授权动作嵌进主流程，而不是单独弹一个授权页。长期订阅消息目前只对特定类目开放，不要指望它。

9审核与合规清单（上线前逐条核）

#项要求风险
1服务类目教育类目需相应资质；先用「工具-效率」或「教育-教育信息服务」试投，按审核反馈调整高
2功能定位表述名称、简介、页面文案中不得出现“搜题”“出答案”“代做”“拍照解题”致命
3内容安全所有用户输入与 AI 输出过 msgSecCheck；图片过 imgSecCheck高
4AI 生成内容标识分析结果页显著提示「由 AI 生成，仅供参考，请以老师讲解为准」中
5题目版权用户协议中明确：用户上传内容版权归原权利人，平台仅提供个人学习用途的整理中
6隐私政策错题含学习数据，属个人信息；需隐私政策 + 用户协议，且要说明 AI 会处理其内容高
7未成年人保护若有中学生用户，需评估未成年人个人信息处理规则中
8第三方数据不得在文案或功能上表现为「官方对接学习通」，避免商标与不正当竞争风险高
第 2 条请当成硬约束写进产品文档。这个品类的审核拒绝理由里，「涉及提供作业答案、存在代写嫌疑」出现频率极高。 我们的功能顺序（先订正、后解析）不只是产品设计，它就是过审的论据。

10上线路线图

MVP 第一阶段 · 验证核心假设

要验证的假设：学生愿意为了「看清自己为什么错」而多花一步去收录。

  • 剪贴板导入 + 截图导入
  • 错题本（筛选：课程 / 知识点 / 状态）
  • 订正流程 + 状态机
  • 错因分析（六大错因）
  • 变式训练（每错题 3 题）
  • 复习提醒（订阅消息）
  • 预置高数 / 线代知识树

不做：电脑端导入助手、组队、班级墙、多学科。

V2 第二阶段 · 提高留存与传播

  • 电脑端「学习通导入助手」（复用现有驱动资产）
  • 知识点掌握度热力图
  • 艾宾浩斯完整排期 + 周报
  • 错题周报分享卡
  • 组队打卡

V3 第三阶段 · 扩展

  • 班级错题墙 / 群入口
  • 考前冲刺包
  • 多学科（物理、计算机等）
  • 教师端（班级共性错因分析）
